# Universal review rules

1. Judge behavior and evidence, not formatting preference.
2. Respect language and framework idioms.
3. Do not impose a specific architecture (Clean Architecture, hexagonal, DDD, microservices, etc.) without a demonstrated need.
4. Do not require abstractions solely for theoretical future reuse.
5. Do not equate short code with simple code or many layers with good architecture.
6. Do not equate test coverage percentage with test quality.
7. Do not infer performance from code appearance; measure or state limits.
8. Do not infer scalability from statelessness alone; inspect bottlenecks and resource limits.
9. Do not call a dependency vulnerable without version and advisory evidence.
10. Do not flag a missing security control unless the relevant attack surface exists.
11. Distinguish product requirements from generic engineering quality.
12. Treat generated code and third-party code separately; identify ownership and scope.
13. Preserve privacy and redact secrets.
14. Be concise and actionable.
